# المرحلة الأولى: النظام الأساسي

## التحقق المنفّذ

- نجح بناء React وفحص TypeScript محليًا وداخل Docker.
- نجحت اختبارات API الثمانية على SQLite وعلى PostgreSQL منفصل للاختبار.
- نجح اختبار متصفح Microsoft Edge للدخول، إنشاء موظف، تحديث الصفحة، الصلاحيات، التعطيل، والخروج، مع فحص عرض الهاتف.
- نجح فحص Nginx → FastAPI → PostgreSQL باستخدام حسابات مؤقتة حُذفت بعد الاختبار.
- نجحت إعادة تشغيل PostgreSQL وAPI مع بقاء إصدار الترحيل `0001` واستعادة اتصال API.
- لا توجد حسابات افتراضية في قاعدة التطبيق؛ يُنشأ المسؤول الأول بالأمر التفاعلي الموضح في README.

## البيانات

`users`: UUID، الاسم، البريد الفريد والمطبّع إلى حروف صغيرة، بصمة كلمة المرور، الدور، حالة التفعيل، وتاريخ الإنشاء.

`access_sessions`: بصمة الرمز العشوائي، مرجع المستخدم، وانتهاء الصلاحية. يتم حذف الجلسات المنتهية عند تسجيل الدخول. يُراجع المستخدم وحالة الحساب في كل طلب محمي، وتُقرأ الصلاحيات من قاعدة البيانات.

## عقد API

| المسار | الطريقة | الوصول | السلوك |
| --- | --- | --- | --- |
| `/api/health` | GET | عام | اختبار API واتصال قاعدة البيانات |
| `/api/auth/login` | POST | عام، مع حماية CSRF | بريد وكلمة مرور؛ تعيين Cookie وإرجاع الحساب |
| `/api/auth/me` | GET | مستخدم نشط | الحساب الحالي |
| `/api/auth/logout` | POST | متاح حتى بعد انتهاء الجلسة | حذف Cookie وإبطال الرمز الحالي |
| `/api/auth/change-password` | POST | مستخدم نشط | كلمة المرور الحالية والجديدة؛ إبطال جميع جلساته |
| `/api/users` | GET | Admin | قائمة المستخدمين |
| `/api/users` | POST | Admin | اسم وبريد وكلمة مرور ودور |
| `/api/users/{id}/status` | PATCH | Admin | تفعيل الحساب أو تعطيله |
| `/api/users/{id}/reset-password` | POST | Admin | كلمة مرور جديدة؛ إبطال جميع جلسات المستخدم |

النجاح: 200 للقراءة والتعديل، 201 لإنشاء حساب، 204 لعمليات الخروج وكلمات المرور. الأخطاء: 400 لعملية غير صالحة، 401 لجلسة أو بيانات دخول غير صالحة، 403 لعدم الصلاحية، 404 لعنصر غير موجود، 409 لبريد مكرر، 422 لفشل التحقق، 429 لتجاوز حد محاولات الدخول.

## خطوات مراجعة يدوية

1. شغّل Docker، أنشئ أول مسؤول ثم سجّل الدخول وحدّث الصفحة؛ يجب بقاء الجلسة.
2. أنشئ Manager وEmployee. افتح نافذة خاصة لكل حساب وتحقق من عدم إتاحة إدارة الفريق.
3. جرّب بريدًا مكررًا وكلمة مرور قصيرة وتحقق من رسائل الخطأ.
4. عطّل حساب الموظف أثناء تسجيل دخوله؛ يجب رفض طلبه المحمي التالي.
5. أعد تفعيله؛ يجب أن يسجّل الدخول مجددًا، دون استعادة الرمز السابق.
6. جرّب تغيير كلمة المرور وإعادة تعيينها؛ تحقّق من إبطال الجلسات السابقة.
7. سجّل الخروج وحدّث الصفحة؛ يجب الرجوع للدخول.
8. أوقف الخدمات ثم أعد تشغيلها وتحقق من بقاء الحسابات.
